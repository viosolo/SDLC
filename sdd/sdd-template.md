## 1. Введение {#1-introduction}

### 1.1 Назначение документа {#11-document-purpose}
Настоящий SDD описывает архитектуру и дизайн веб-приложения «Viosolocake» на основе утвержденного документа SRS версии 0.2. Документ предназначен для команды разработчиков (Frontend и Backend), тестировщиков и архитекторов для понимания того, как система будет реализована технически.

### 1.2 Область применения {#12-subject-scope}
Проектируемая система — веб-приложение интернет-магазина кондитерских изделий. Включает клиентскую часть (SPA) для покупателей, административную панель для сотрудников и серверную логику для обработки заказов. Система не включает нативные мобильные приложения и модуль онлайн-оплаты (согласно границам проекта в SRS).

### 1.3 Определения, акронимы и сокращения {#13-definitions-acronyms-and-abbreviations}
| Term | Definition |
|------|------------|
| API | Application Programming Interface — программный интерфейс взаимодействия |
| SDD | Software Design Document — документ описания дизайна ПО |
| SPA | Single Page Application — одностраничное веб-приложение |
| JPA | Java Persistence API — спецификация для работы с БД в Java |
| Vite | Сборщик модулей для быстрой разработки и сборки Frontend |

### 1.4 Ссылки {#14-references}
* Спецификация требований (SRS) «Viosolocake» версия 0.2 (Нормативная).
* IEEE 1016-2009 Systems and software engineering — Software design description (Справочная).

### 1.5 Обзор документа {#15-document-overview}
Документ состоит из 5 разделов. Раздел 2 описывает задачи стейкхолдеров и выбранные точки зрения. Раздел 3 содержит конкретные проектные представления (архитектуру). Раздел 4 фиксирует ключевые архитектурные решения (ADR). Раздел 5 включает дополнительные материалы.

## 2. Обзор дизайна {#2-design-overview}

### 2.1 Задачи стейкхолдеров {#21-stakeholder-concerns}
* **Заказчик:** заинтересован в быстрой работе сайта, надежном сохранении заказов и защите данных клиентов.
* **Frontend-разработчики:** нуждаются в четком описании контрактов REST API для интеграции React с сервером.
* **Backend-разработчики:** нуждаются в понимании структуры базы данных и бизнес-логики обработки корзины и заказов.
* **QA-инженеры:** нуждаются в понимании статусных моделей (например, жизненного цикла заказа) для написания тест-кейсов.

### 2.2 Выбранные точки зрения {#22-selected-viewpoints}
Для описания системы выбраны 9 ключевых точек зрения согласно стандарту ISO 42010. Для каждой точки зрения определен свой язык моделирования.

#### 2.2.1 Контекст {#221-context}
**Адресует**: границы системы, акторы окружения и предоставляемые сервисы.
**Применение в проекте**: Описание взаимодействия с Покупателем, Администратором, SMTP-сервером и сервисом доставки.
**Выбранный язык моделирования**: Контекстная диаграмма (C4 Context Diagram).

#### 2.2.2 Композиция {#222-composition}
**Адресует**: выявление основных элементов дизайна, распределение ответственности и интеграция.
**Применение в проекте**: Описание клиент-серверной архитектуры (React SPA, Java Spring Boot, PostgreSQL).
**Выбранный язык моделирования**: Диаграмма компонентов UML.

#### 2.2.3 Логическое представление {#223-logical}
**Адресует**: статическую структуру дизайна с точки зрения типов и их взаимосвязей.
**Применение в проекте**: Описание объектной модели данных (сущности Spring Data JPA) и их связей.
**Выбранный язык моделирования**: Диаграмма классов UML.

#### 2.2.5 Структура {#225-structure}
**Адресует**: внутреннюю организацию компонентов, их частей и коннекторов.
**Применение в проекте**: Описание слоевой архитектуры Backend (паттерн MVC: Controller, Service, Repository).
**Выбранный язык моделирования**: Диаграмма композитной структуры UML.

#### 2.2.7 Информация {#227-information}
**Адресует**: структуру постоянных данных, их связи и механизмы доступа.
**Применение в проекте**: Описание реляционной схемы базы данных PostgreSQL.
**Выбранный язык моделирования**: ER-диаграмма (сущность-связь).

#### 2.2.8 Интерфейс {#228-interface}
**Адресует**: внешние видимые интерфейсы между компонентами или с внешними системами.
**Применение в проекте**: Спецификация REST API для обмена данными между React и Java.
**Выбранный язык моделирования**: Спецификация OpenAPI (Swagger).

#### 2.2.11 Динамика состояний {#2211-state-dynamics}
**Адресует**: эволюцию состояний системы или компонента в ответ на события.
**Применение в проекте**: Описание жизненного цикла заказа (от создания до выполнения).
**Выбранный язык моделирования**: Диаграмма состояний UML (State Machine).

#### 2.2.13 Паттерны {#2213-patterns}
**Адресует**: повторно используемые идеи дизайна и архитектурные стили.
**Применение в проекте**: Использование архитектурных паттернов MVC и REST.
**Выбранный язык моделирования**: Текстовое описание паттернов и диаграмма пакетов UML.

#### 2.2.14 Развёртывание {#2214-deployment}
**Адресует**: отображение программных сущностей на физическое окружение выполнения.
**Применение в проекте**: Описание развертывания Docker-контейнеров на VPS.
**Выбранный язык моделирования**: Диаграмма развёртывания UML.

## 3. Проектные представления {#3-design-views}

**ID:** 001-context  
**Title:** Контекст системы  
**Viewpoint:** Контекст  
**Representation:** Система «Viosolocake» выступает центральным компонентом. Акторы: Покупатель (браузер), Администратор. Внешние системы: SMTP-сервер (отправка чеков), сервис доставки.  
**More Information:** Реализует требования `REQ-INT-009`, `REQ-INT-010`.

**ID:** 002-composition  
**Title:** Композиция и архитектура  
**Viewpoint:** Композиция  
**Representation:** Клиент-серверная архитектура. Состоит из 3 уровней: Frontend (React SPA на Vite с использованием JS), Backend (Java Spring Boot с REST-контроллерами), Database (PostgreSQL).  
**More Information:** Реализует требования `REQ-FUNC-001`, `REQ-FUNC-004`, `REQ-FUNC-006`.

**ID:** 003-structure  
**Title:** Слоевая структура Backend  
**Viewpoint:** Структура  
**Representation:** Backend разделен на слои: Контроллеры (принимают HTTP-запросы), Сервисы (бизнес-логика), Репозитории (взаимодействие с БД).  
**More Information:** Обеспечивает слабую связность и тестируемость кода (`REQ-MAINT-001`).

**ID:** 004-information  
**Title:** Модель данных  
**Viewpoint:** Информация  
**Representation:** Реляционная база данных. Основные таблицы: `Users` (id, email, password_hash, role), `Products` (id, name, price, category_id), `Orders` (id, user_id, status, total_price).  
**More Information:** Реализует требования `REQ-FUNC-007`, `REQ-FUNC-008`.

**ID:** 005-interface  
**Title:** REST API Контракты  
**Viewpoint:** Интерфейс  
**Representation:** Обмен JSON-сообщениями по HTTP.  
* `GET /api/products` — каталог (`REQ-FUNC-001`).  
* `POST /api/cart` — корзина (`REQ-FUNC-004`).  
* `POST /api/orders` — оформление заказа (`REQ-FUNC-006`).  
**More Information:** Реализует требование `REQ-INT-011`.

**ID:** 006-state-dynamics  
**Title:** Жизненный цикл заказа  
**Viewpoint:** Динамика состояний  
**Representation:** Статусы заказа: `Новый` -> `В обработке` -> `Готов` -> `Выполнен`. Переход между статусами осуществляется администратором.  
**More Information:** Реализует требование `REQ-FUNC-009`.

**ID:** 007-deployment  
**Title:** Развёртывание системы  
**Viewpoint:** Развёртывание  
**Representation:** Приложение упаковано в Docker-контейнеры. Развертывание на VPS. Веб-сервер Nginx раздает статику React (собранную Vite) и проксирует запросы к Java-приложению.  
**More Information:** Реализует требование `REQ-INST-001`.

## 4. Решения {#4-decisions}

**ID:** ADR-001  
**Title:** Выбор Java Spring Boot для Backend  
**Context:** Необходимо создать надежный, безопасный REST API, который будет легко масштабировать и интегрировать с реляционной БД.  
**Options:** Node.js + Express, Python + Django, Java + Spring Boot.  
**Outcome:** Выбран Java + Spring Boot. Обоснование: строгая типизация, встроенные механизмы безопасности (Spring Security) и зрелая экосистема (Spring Data JPA).  
**More Information:** Влияет на архитектурный слой `002-composition`.

**ID:** ADR-002  
**Title:** Выбор стека Vite + React (JavaScript) для Frontend  
**Context:** Требуется создать быстрый, реактивный и легко поддерживаемый пользовательский интерфейс (SPA) без избыточной сложности.  
**Options:** Angular, Vue.js, React (с Vite).  
**Outcome:** Выбран стек Vite + React + JS. Обоснование: Vite обеспечивает мгновенную сборку и горячую замену модулей (HMR), а React на JavaScript имеет огромную экосистему компонентов и низкий порог входа по сравнению с Angular.  
**More Information:** Влияет на клиентскую часть в `002-composition`.

**ID:** ADR-003  
**Title:** Выбор PostgreSQL для базы данных  
**Context:** Требуется хранить заказы (транзакции) и данные пользователей без риска потери целостности данных при одновременных запросах.  
**Options:** MySQL, MongoDB, PostgreSQL.  
**Outcome:** Выбран PostgreSQL. Обоснование: полная поддержка ACID-транзакций и бесплатная лицензия.  
**More Information:** Влияет на модель данных `004-information`.
