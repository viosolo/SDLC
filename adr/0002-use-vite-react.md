# Выбор Vite + React для Frontend

## Контекст и постановка задачи
Требуется создать интерактивный пользовательский интерфейс (SPA), который будет быстро работать в браузере, моментально реагировать на действия пользователя и легко связываться с REST API на бэкенде.

## Драйверы решения
* Скорость сборки и разработки.
* Высокая производительность интерфейса (`REQ-PERF-001`).
* Огромное сообщество и наличие готовых UI-компонентов.

## Рассмотренные варианты
* Angular
* Vue.js
* React (с использованием сборщика Vite)

## Итог решения
Выбран вариант **«React (с Vite)»**, так как Vite обеспечивает мгновенную сборку, а React дает максимальную гибкость и огромную базу библиотек.

### Последствия
* **Хорошо**, потому что благодаря Vite (HMR) изменения в коде отображаются в браузере моментально, а React позволяет переиспользовать компоненты.
* **Плохо**, потому что экосистема React очень быстро меняется, и разработчикам нужно постоянно следить за обновлениями (например, появление Server Components).

### Подтверждение
Проверка соблюдения архитектуры SPA и отсутствия лишних перерисовок компонентов через тесты производительности (Lighthouse).

## Плюсы и минусы вариантов

### Angular
* Хорошо, потому что это полноценный фреймворк со встроенной архитектурой.
* Плохо, потому что избыточно сложен для данного размера проекта, и Vite с ним работает не так гладко.

### Vue.js
* Хорошо, потому что низкий порог входа и понятный синтаксис.
* Плохо, потому что меньшее количество готовых enterprise-решений по сравнению с React.

### React (с Vite)
* Хорошо, потому что самая популярная библиотека, легко найти разработчиков и готовые компоненты.
* Плохо, потому что требует самостоятельного выбора дополнительных библиотек (роутинг, стейт-менеджмент).
